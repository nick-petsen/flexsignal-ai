# Frozen hourly EDS backtest input (P0.9a)

`scripts/build_hourly_eds_backtest_input.py` builds a local, read-only historical
input from the four P0.8 archives for DK1 and DK2. It makes no API or database
calls and runs no forecast, risk score, or backtest. The archives remain local
and ignored by Git.

```sh
python3 scripts/build_hourly_eds_backtest_input.py \
  --archive-root /path/to/public-eds-inputs \
  --output /path/outside/archives/hourly-eds-input.json
```

`--archive-root` is required. `--output` is optional; without it the builder
validates and computes all rows, then prints only the summary. With it, the
builder writes deterministic UTF-8 JSON and prints the same DK1/DK2 counts,
exclusive UTC period, and SHA-256 of the JSON bytes. Write output outside the
archive root. The expected period is `[2026-04-01T00:00:00Z,
2026-04-08T00:00:00Z)`: 168 rows per area, 336 total.

The builder uses P0.8 manifest integrity, price-area, UTC interval, duplicate,
and cross-dataset alignment checks before computing anything. It groups the
four `DayAheadPrices` quarters in each UTC hour, requires a numeric
`DayAheadPriceEUR` in every quarter, and takes their arithmetic mean with
decimal arithmetic. It then joins the matching hourly
`ProductionConsumptionSettlement` row for the same area and UTC hour. Rows are
ordered by DK1, then DK2, and ascending UTC hour within each area.

Each output row has `price_area`, `hour_utc`, `price_eur_per_mwh`, and
`settlement_observed`. The hourly price is an exact decimal string in EUR/MWh.
`settlement_observed` contains the source settlement fields apart from
`PriceArea` and `HourUTC`. Present `null` values stay `null`; absent fields
stay absent. Decimal source numbers are serialized as strings to preserve their
precision. The builder does not fill, estimate, or derive production or
consumption values. Source archives and manifests are the provenance for the
input; the output hash identifies the generated bytes, not the API origin.

This is **observed historical data**. Settlement production and consumption
can be published or revised after the hour. A historical day-ahead price value
also does not, by itself, establish when that particular value or archive
revision became available. A forecast backtest must separately record the
forecast issuance time, source publication and revision timing, and the exact
data visible at issuance. This builder neither establishes forecast accuracy
nor prevents look-ahead bias in later backtests. It does not validate the
published surplus-risk snapshot or its historical performance claims.
